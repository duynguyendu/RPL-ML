\section{\ieeemac{}}
\ieeemac{} is a technical standard that defines the physical layer
(PHY) and media access control (MAC) for Low Rate
Wireless Personal Area Networks (LR-WPANs),
targetting devices bounded by low computing
power, memory and energy \cite{salmanOverviewIEEE8021542010}. It is
designed to operate in Personal
Operating Space (POS) of 10 meters or less and supports
three types of topology: star, peer-to-peer and mesh (a network
    that connects a large number of
nodes through relaying messages). The standard offers three free bands
throughout the world with the throughput of 250\,kbps in the 2.4\,GHz
band 40\,kbps at 915\,MHz and 20\,kbps at 868\,MHz.

The 802.15.4 standard controls channel access with Carrier-Sense
Multiple Access with
Collision Avoidance (CSMA/CA). It defines two mode:
beacon-enabled for synchronous access and non-beacon-enabled for
asynchronous access.

In non-beacond-enabled mode, nodes use unslotted
CSMA/CA, and they do not exchange request-to-send (RTS) and clear-to-send (CTS)
messages. When a node has packets to send, it delays the transmission for a
random backoff period. Afterward, it senses the medium and transmit
only if the channel is idle. If the channel is busy, the node waits for
another random backoff period and check the channel again.
Because transmissions are not synchronised, packets can arrive at any
time. As a result, nodes that may receive data have to keep their
radio on at all time.
This is especially costly in multihop topologies where nodes must
also relay messages for other nodes.

In beacon-enabled mode, the coordinator cuts time into superframes,
which consists of 16 equally sized slots. Each
superframe starts when the coordinator sends a beacon to synchronise
the nodes. Each superframe has an active period and an optional
inactive period. During the active period, nodes compete for the
channel using slotted CSMA/CA, with backoff period aligned to the
slot boundary. During the inactive period, nodes can turn off their
radios until the next beacon to save energy.

\section{\ieeemacE{} (TSCH)}
The IEEE 802.15.4e amendment introduced Time-Slotted Channel Hopping
(TSCH), a tightly synchronised MAC mode for \ieeemacE{} networks, and
RFC~7554 describes how TSCH is used in the context of IPv6-based
low-power networks \cite{rfc7554}. In a TSCH network, time is divided
into timeslots, and a group of consecutive timeslots forms a
\emph{slotframe}, which repeats over time. In addition, TSCH
transmits on different channels at different times, as illustrated in
Figure~\ref{fig:tsch}.

\begin{figure}
    \begin{center}
        \includegraphics[width=0.9\textwidth]{assets/TSCH.png}
    \end{center}
    \caption{TSCH time slot visualisation.}\label{fig:tsch}
\end{figure}

A timeslot, typically 10\,ms long, is long enough for a node to
transmit a frame and for the receiver to send back an
acknowledgement, and both must finish within that slot. In each
timeslot, a node either transmits, receives or sleeps. A node with a
frame to send waits for a timeslot in which it is scheduled to
transmit, and then starts sending at a fixed offset from the start of
the slot. A node scheduled to receive turns on its radio shortly
before the expected start of the frame. If no frame begins within
this short guard time, it turns its radio off again for the rest of
the slot to save energy.

TSCH also uses channel hopping: successive transmissions over the
same link use different frequencies. Hopping provides frequency
diversity, which reduces the impact of external interference and
multipath fading. Because each link is assigned a channel offset,
several pairs of nodes can also communicate at the same time on
different channels. Each timeslot is identified by the Absolute Slot
Number (ASN), the total number of timeslots that have elapsed since
the network started. Let $\mathit{chOf}$ be the channel offset
assigned to a link. The frequency $f$ used for a transmission in that
link is then
\begin{equation}
    f = F\left[(\mathit{ASN} + \mathit{chOf}) \bmod
    n_{\mathit{freq}}\right],
\end{equation}
where $n_{\mathit{freq}}$ is the number of available channels (16 in
the 2.4\,GHz band) and $F$ is a lookup table that maps an index to a
physical channel. Since the ASN increases with every timeslot, the
same link uses a different frequency each time it is scheduled, while
the two nodes on the link always agree on which frequency to use.

TSCH avoids collisions through its schedule. Each transmission
opportunity is a \emph{cell}, identified by a slot offset within the
slotframe and a channel offset. In a \emph{dedicated} cell, only one
transmitter is scheduled, so the transmission is free of contention.
In a \emph{shared} cell, several nodes may transmit, and collisions
are handled by a CSMA/CA-like backoff. As long as neighbouring links
are assigned different cells, their transmissions do not interfere.

\ieeemacE{} specifies how a TSCH schedule is executed, but not how it
is built or maintained. These tasks are left to higher layers. The
6TiSCH working group of the IETF defines protocols for this purpose,
such as the 6TiSCH Operation Sublayer (6top) and the Minimal
Scheduling Function \cite{rfc9033}, and autonomous schedulers such as
Orchestra \cite{duquennoy2015orchestra} derive the schedule locally
from the routing topology.

Compared with CSMA/CA, TSCH is more complex and requires network-wide
time synchronisation. In return, it offers higher reliability and
lower energy consumption, since nodes keep their radios on only in
the timeslots in which they are scheduled. The cost is higher
latency, because a node must wait for its next scheduled cell before
it can transmit, so delay depends on the length of the slotframe.

\section{IPv6 over Low-Power Wireless Personal Area Networks (6LoWPAN)}
Before this, people used proprietary protocols and link-only solution
such as ZigBee, given that the IP was too computational and memory
heavy for these low-power devices.

6LoWPAN is a protocol applying IPv6 to low-power devices operating on
top of low power wireless networks, specifically \ieeemac{} PHY and MAC layers.
6LoWPAN introduces an adapatation layer between IPv6 and network
layers to establish efficient transmission of IPv6 datagrams over
802.15.4 links by compressing the header to reduce transmission
overhead, fragmentation to support minimum MTU requirement and
layer-two forwarding

- Header compression
- Fragmentation: Normally, the IPv6 payload does not fit the payload
of \ieeemac{}, 6LoWPAN is crucial by providing scheme to assemble
fragmented packets over multiple hops.
- Layer-two forwarding: the adaptation layer can carry link-level
addresses for the ends of an IP hop

Protocol, simplifying the connection between different networks and
reduce the complexity of the gateways that were needed to translate
between proprietary protocl and standard Internet Protocol.
