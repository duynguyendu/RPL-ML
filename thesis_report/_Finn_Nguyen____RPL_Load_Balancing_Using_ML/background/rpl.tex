\section{Routing Protocol for Low-Power and Lossy Networks (RPL)}

RPL is an oriented distance vector routing protocol, operating on top of
IEEE 802.15.4 PHY and MAC-layer and over 6LoWPAN (IPv6 over Low-Power
Wireless Personal Area Networks). Its main target is Wireless
Sensor Networks (WSNs),
where multipoint-to-point is the predominant communication pattern.
Routes in RPL are optimised for traffic to or from one or more
roots in the topology, while maintaining reliable and energy
efficient data collection. To sustain this, RPL is designed adapt to various
network conditions, allowing nodes to switch route when route
degradation is detected.

\subsection{Destination-Oriented Directed Acyclic Graph (DODAG)}
In principle, RPL organises nodes under a DODAG, with the sink
node of the WSN often serving as the root of DODAG.
When a packet need to be sent to the sink node, the
packet traverse the path in DODAG until it reach the root node. The
acyclic nature of DODAG ensures that the packet does not get stuck in
endless circle.

There are four identifiers to define maintain a topology in RPL
Table~\ref{tab:rpl-identifiers}, with RPLInstanceID and DODAGID used
to identify a single DODAG in the network.

During DODAG construction, each node selects parent from its pool of
potential nodes that have path to the root through objective
function, which translates one or
more metrics into rank and determines how to select the best parent.
The equation of the rank is calculated as
\[
    Rank(N) = Rank(P) + Rank\_Increase
\]
where $Rank(N)$ is the rank of the current node, $Rank(P)$ is the
rank advertised by a node and $Rank\_Increase$ is determined by OF,
which can be considered as the cost of choosing $P$ as parent.

To begin forming DODAG, the root node starts sending DIO to its neighbouring
nodes. Upon receiving DIO, a node decides whether to join the
advertised DODAG or not. To prevent loops, a node only considers a
DIO if it advertises a rank lower than its own rank.
In certain implementations, a node would wait for several DIOs to
build the pool of candidate parents before deciding.
Afterward, the node computes the path cost of the
corresponding link for each candidate and selects the candidate with
the lowest path cost as its preferred parent. Once a parent has been
selected, the node broadcasts its own DIO to
advertise itself to its neighbours. This process is done until all
the nodes have join the DODAG.

A node would send DAO message back to the root node after it has

Afterward, the nodes broadcast its DIO to advertise itself to the

In the DAO-ACK mode, a node wait
for the root node to send back DAO-ACK
before confirming that it is reachable and advertise DIO to surrounding nodes

\subsection{Trickle Timer}
DIO is crucial in forming and maintaining DODAG, thus RPL also employs
Trickle timer to regulate the emission of DIO.
Trickle timer works by adjusting the sending interval dynamically
based on the packets and network condition to ensure timely send
while reducing redundant message transmission.
The Trickle timer does this by evaluating the consistency of the
network. When the network information are consistent, it
exponentially increases the transmission interval of DIO. However,
upon detecting inconsistencies, trickle timer reset its send interval
to boost DIO transmission to spread the latest information to the DODAG.

Table~\ref{tab:tricker_timer_params} shows three configuration
parameters: Imin, Imax and k that Tricker timer to determine the send
interval.
The maximum sending interval time is:
\[
    I_{max\_time} = I_{min} \times 2^{I_{max}}
\]

$[I_{min}, I_{max\_time}]$, usually the initial interval is set to $I = I_{min}$

\subsection{Communication Patterns}
There are two types of communication patterns in RPL: upward route
and downward route
\subsubsection{Upward Route}
In this approach, the upward routes follow the DODAG path to root as
presented in the earlier section. A node would select one node as a
preferred parent according the the rank calculated from OF

\subsubsection{Downward Route}
The downward are supported to P2MP and P2P route, in which the
destination is not the root node. In this pattern, the node sends DAO
to its preferred parent in a unicast manner

% TODO: study the storing mode more
In this pattern, the RPL specification defines two mode: storing mode
and non-storing mode. In storing mode, the downward routing tables
are included in each nodes
However, in non-storing mode, the downward routing tables are stored
only in the DODAG root. This means that P2P communication need to be
forwarded to the root node, where the root would then formulate the
routing path to the downward node.
