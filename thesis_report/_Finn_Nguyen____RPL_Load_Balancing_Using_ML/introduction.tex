Various projects need to deploy a large number of constrained
devices, which are limited by computational power, memory and energy
usage (battery), to cover large geographic areas. Because the
underlying network technologies are limited in range, multi-hop
routing solution is often required. Such networks are categorised as
Low-power and Lossy Networks (LLN). Additionally, links in LLN are
susceptible to loss and frequent packet drops.

These constrains led the Internet Engineering Task Force (IETF),
which is an international organisation of network designers and
researcher, to form Routing over Low-power and Lossy networks (ROLL)
working group, investigating the routing solution for LLNs.

The ROLL first published RFC 5548 \cite{rfc5548}, RFC 5673
\cite{rfc5673}, RFC 5826 \cite{rfc5826}, RFC 5867 \cite{rfc5867} to
define the routing requirements for smart urban, industrial area,
home automation and building automation applications respectively.
Building on these requirements, ROLL proposed a new routing protocol
designed specifically for LLN called IPv6 based routing protocol for
low power and lossy networks (RPL), standardised in RFC 6550
\cite{alexanderRPLIPv6Routing2012}. Since its standardised, RPL has
been employed in various settings and applications. % TODO: backup these claim

At its core, RPL constructs a Destination-Oriented Directed Acyclic
Graph (DODAG) to route packets from nodes toward a root, using
objective function (OF) to calculate path cost and select parents
during DODAG construction. Because of this, OFs determine how the
traffic is distributed across DODAG. % TODO: talk a bit more about this

The protocol fell short when it comes to performing under load as
load balancing was not considered in the design. Moreover, most of
the OFs are reactive in nature, meaning that would react after a
route has degraded, leading to decrease in network quality and reliability.
