\section{Feature Selection}
% TODO: review this section
Feature selection is the process of choosing a subset of the available
input features that are most relevant to the prediction target, and
discarding those that are redundant or uninformative. Using fewer
features reduces the risk of overfitting, makes the model easier to
interpret and, most importantly for this work, reduces the size of the
model and the cost of inference on a constrained device. It also
reduces the number of metrics each node must measure and share with
its neighbours.

Closely related is \emph{feature importance analysis}, which
quantifies how much each feature contributes to a model's
predictions. Feature importance scores are often used to rank the
features, and the ranking then guides which features to keep. Feature
selection methods are commonly grouped into three families: filter,
wrapper and embedded methods.

\paragraph{Filter methods} assess each feature by its statistical
relationship with the target variable, independently of any machine
learning model. The features are ranked by a score and the
lowest-ranked ones are removed. Filter methods are fast and
model-agnostic, but they evaluate each feature in isolation and so can
miss interactions between features. Common scores include:
\begin{itemize}
    \item \textbf{Pearson correlation coefficient}, which measures the
        strength of the linear relationship between two continuous
        variables;
    \item \textbf{Spearman rank correlation coefficient}, which
        measures the strength of a monotonic relationship, whether linear
        or not, and also applies to ordinal variables;
    \item \textbf{Mutual information}, which measures how much knowing
        one variable reduces uncertainty about the other, and so captures
        any kind of dependency, including non-monotonic ones;
    \item \textbf{Variance threshold}, which removes features whose
        values barely change and therefore carry little information.
\end{itemize}

\paragraph{Wrapper methods} use the performance of a machine learning
model as the score for a subset of features. The model is trained and
evaluated on different subsets, and the subset with the best
performance is kept. A common example is \emph{sequential backward
selection} (SBS), which starts with all features and repeatedly
removes the feature whose removal hurts the performance least, until
the performance drops below an acceptable level. Wrapper methods
account for interactions between features and for the behaviour of
the model in use, but they are computationally expensive, because the
model must be retrained for every subset evaluated.

\paragraph{Embedded methods} perform feature selection as part of
training the model. For example, decision trees and gradient-boosted
trees such as LightGBM choose, at each split, the feature that most
reduces the prediction error. Features that are never chosen have no
effect on the model. These models also report a built-in importance,
such as the mean decrease in impurity (MDI) or the number of splits
on each feature. However, these built-in scores are calculated on the
training data. They also tend to favour features with many distinct
values over low-cardinality features, such as the binary
\texttt{is\_new}, and they are not comparable across model types.

In addition to these three families, \emph{model-agnostic}
interpretation methods can measure feature importance for any fitted
model. Two widely used examples are permutation importance
\cite{altmannPermutationImportanceCorrected2010} and SHapley Additive
exPlanations (SHAP) \cite{lundbergUnifiedApproachInterpreting2017},
both described below. Unlike built-in importances, they can be
calculated on held-out data, and their scores can be compared directly
across the decision tree and LightGBM models.

In this work, we combine these approaches. Before training, Spearman
and Pearson correlations are used as a filter method to identify
redundant features and to measure each feature's relationship with
the PDR. After training, permutation importance and SHAP are used to
rank the features for each model. Finally, in a wrapper-style step,
the lowest-ranked features are removed one at a time and the model is
retrained, until its error exceeds the best model's error by more than
1\%.

\subsection{Permutation Importance}
Permutation importance \cite{altmannPermutationImportanceCorrected2010}
is a model inspection technique that measures how much each feature
contributes to a fitted model's performance on a tabular dataset. It
treats the model as a black box: it only needs the model's
predictions, not its internal structure. This makes it suitable for
non-linear models such as decision trees and LightGBM, and its scores
can be compared directly across model types.

The idea is that if a feature is important, breaking its link with
the output should make the model's predictions worse. The method
first measures the model's baseline score $s$ on a dataset. Then, for
each feature $j$, it randomly shuffles that feature's values across
the rows, which keeps the feature's distribution but removes its
relationship with the PDR. The model is scored on this corrupted
dataset, and the shuffle is repeated $K$ times to reduce the effect
of randomness. The importance of feature $j$ is the average drop in
score:
\begin{equation}
    i_j = s - \frac{1}{K} \sum_{k=1}^{K} s_{k,j},
\end{equation}
where $s_{k,j}$ is the score after the $k$-th shuffle of feature $j$.
In this work, the score is the negative mean absolute error, so
$i_j$ is the average increase in prediction error when feature $j$
is shuffled. We use $K = 10$, and compute the importance on a
held-out test set of 20\% of the data, so that it reflects how the
model generalises rather than what it memorised during training.

Permutation importance avoids the main weaknesses of the mean
decrease in impurity (MDI) described above. MDI is calculated from
the training data and favours features with many distinct values,
such as ETX, over low-cardinality features such as the binary
\texttt{is\_new}. Permutation importance does not depend on how the
model splits the data, so it has no such bias, and it can be computed
on unseen data.

However, permutation importance has two limitations. First, it
measures how much the model's \emph{error} depends on a feature, not
how the feature changes the model's \emph{prediction}. Its scores are
only meaningful if the model is accurate, and they do not show
whether a feature pushes the predicted PDR up or down. Second, when
two features are strongly correlated, such as ETX and hop count,
shuffling one of them has little effect because the model can still
rely on the other. Both features may then appear less important than
they really are. Shuffling can also create unrealistic inputs, such
as a node with a high hop count but a very low ETX. SHAP, described
next, addresses the first limitation by measuring each feature's
contribution to every individual prediction.
