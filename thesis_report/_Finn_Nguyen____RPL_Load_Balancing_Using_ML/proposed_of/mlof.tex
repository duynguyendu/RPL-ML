\section{Proposed Objective Function MLOF}

Most existing OFs rely on a single routing metric. As a result, they
behave greedily: a node selects the neighbour with the best link
quality without considering the performance of the route as a whole.
To address this, we use machine learning to analyse which routing
metrics most strongly affect the quality of a parent's chain from
current node to root. The resulting feature importance then guides
the design of a more effective OF.

Among the ML-based OFs reviewed in Section~\ref{sec:related-work},
most are based on reinforcement learning. The one supervised approach
predicts only the probability that a single packet is transmitted
successfully, which does not capture the longer-term behaviour of the
link.

The proposed OF instead uses an ML model to predict the packet
delivery ratio (PDR) of a link, so that nodes avoid heavily loaded
paths. The predicted PDR is combined with ETX to compute the rank
increase:
\begin{equation}
    \mathit{Rank\_Increase} = \alpha \times \mathit{Predicted\_PDR} +
    (1 - \alpha) \times \mathit{ETX}
\end{equation}

We include ETX as a measure to control the prediciton of the model
incase of wild prediction, which could lead to unstable DODAG and
reduce the network performance.

In the end, we collected seven routing metrics
\begin{itemize}
    \item ETX: Expected Transmission Count so a packet would be sent
        and receive acknowledgement
    \item Hop count: the number of hop to get to the parent node
    \item RSSI: The receiving signal strength of the parent
    \item Packet per minute (PPM): the number of packets going
        through the current node, included all of its children %
        % TODO: specify this is MAc packets
    \item Drop rate: the number of transmission per drop of the current node
    \item Path weighted PPM: the weighted number of packets going
        through the parent nodej for the whole path
    \item Path weighted drop rate: the weighted drop rate of the
        parent node for the whole path
\end{itemize}
and two node metrics:
\begin{itemize}
    \item CPU Util: the percentage of time in CPU util
    \item Path weighted CPU util: the weighted percentage of time in
        CPU util for the whole path
\end{itemize}

    \item Is new: differentiate the DIO update from old parent or new parent
