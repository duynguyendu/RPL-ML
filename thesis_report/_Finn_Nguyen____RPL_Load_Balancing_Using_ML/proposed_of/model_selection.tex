\section{Regression Machine Learning Model Selection}
Since we embed the model into the OF, the model must be lightweight,
fast at inference and fit in tight memory of the devices in LLN.
As most microcontrollers used in LLNs lack a floating-point unit,
the model must avoid floating-point arithmetic. On these
devices, floating-point operations are emulated in software, which is
slow and increases code size. A common workaround is
\emph{quantisation}, which represents the model's parameters and
inputs as fixed-point integers
\cite{hasanpourSurveyQuantizationTechniques2025}. As such, the
chosen model must either need no floating-point arithmetic at all, or
remain accurate once quantised. Specifically, the model ported to C code must:
\begin{itemize}
    \item Compile to C code of less than 5\,KB, so that the model
        adds little to the size of the RPL firmware,
    \item Use no floating-point operations during inference, and
    \item Run inference in a short time to avoid delay parent
        selection and consume CPU for other tasks.
\end{itemize}

With these requirements in mind, we considered seven regression
models: K-nearest neighbour regression, linear regression, support
vector regression, Gaussian process regression, decision tree and
ensemble trees (LightGBM). Each is described below, along
with whether it meets
the requirement of size constrained. In model evaluation, we analyse
how the models perform after quantisation.

\subsubsection{K-Nearest Neighbor Regression (KNNR)}
KNNR is a simple model based on the idea that points close to each
other in feature space have similar output values. To predict the
value of an unseen point $\mathbf{x}$, it finds the $k$ neighbours nearest to
$\mathbf{x}$, and averages the neighbours values:
\begin{equation}
    \hat{y}(\mathbf{x}) = \frac{1}{k} \sum_{i=1}^{k} y_i
\end{equation}
Alternatively, each neighbour can be weighted by the inverse of its
distance to $\mathbf{x}$, so that closer neighbours contribute more
to the prediction:
\begin{equation}
    \hat{y}(\mathbf{x}) = \frac{\sum_{i=1}^{k} w_i y_i}{\sum_{i=1}^{k} w_i},
    \qquad w_i = \frac{1}{d(\mathbf{x}, \mathbf{x}_i)}
\end{equation}

Some common distance choice in KNNR includes Euclidean distance,
Manhattan distance, the Minkowski
distance and so on. The value of $k$ depends on the
application and is usually chosen by a hyperparameter search. Because
KNNR relies on distances between points, features with large ranges
can dominate those with small ranges, so normalising or scaling the
features often improves its accuracy.

KNNR does not need training since the model stores the training data
and uses it at inference.
However, this means that KNNR does not fit into our memory
requirement. The whole
training dataset must be stored on the device, which far exceeds the
5\,KB limit. Each prediction must also compute the distance to every
one of the $n$ training points, each with $m$ features at a cost of
$O(nm)$, which is
expensive for a constrained device.

\subsubsection{Linear Regression}
% TODO: insert citation for this
Linear regression is a parametric model that assumes the output is a
weighted sum of the input features. For an input
$\mathbf{x} = (x_1, \dots, x_m)$ with $m$ features, the prediction is
\begin{equation}
    \hat{y}(\mathbf{x}) = c_0 + \sum_{j=1}^{m} c_j x_j
\end{equation}
where $c_0$ is the intercept and $c_j$ is the coefficient of
feature $j$. Training picks the coefficients that minimise the squared
error over the $n$ training points.

Linear regression fits the size requirement as
the model only contains $m+1$ coefficients, a mean and scale for each
feature. A prediction costs $O(m)$ from $m$ multiply-add operations, and
does not depend on the size of the training data. In the evaluation, we use the
ridge regression, which adds a penalty on the
size of the coefficients to reduce overfitting and the effect of
correlated features. The features are standardised before fitting,
so that features with large ranges, such as ETX, do not dominate
features with small ranges, such as hop count.

\subsubsection{Support Vector Regression}
% TODO: insert citation for this
% TODO: maybe include separating hyperplan
Support Vector Regression (SVR) is a regression method based on the
Support Vector Machine (SVM). It ignores errors smaller than a margin
$\varepsilon$ and penalises only the points that fall outside it,
which makes it less sensitive to small noise. The prediction for an
input $\mathbf{x}$ is
\begin{equation}
    \hat{y}(\mathbf{x}) = c_0 + \sum_{i \in \mathcal{S}} a_i \,
    K(\mathbf{x}_i, \mathbf{x}),
\end{equation}
where $\mathcal{S}$ is the set of support vectors (the training points
that lie on or outside the margin), $a_i$ is the coefficient learned
for support vector $i$, $c_0$ is a bias term, and $K(\cdot,\cdot)$ is
a kernel function that measures the similarity between two inputs.

With a linear kernel $K(\mathbf{x}_i, \mathbf{x}) =
\mathbf{x}_i \cdot \mathbf{x}$, the model becomes linear SVR, which
predicts with the same weighted sum as linear regression
\begin{equation}
    \hat{y}(\mathbf{x}) = c_0 + \sum_{j=1}^{m} c_j x_j,
\end{equation}
% TODO: this sentence
but fits the coefficients differently: errors smaller than $\varepsilon$ are
ignored and larger errors are penalised linearly rather than quadratically,
making it less sensitive to outliers than least squares.

With a nonlinear kernel, the inputs are implicitly mapped to a
higher-dimensional feature space (the \emph{kernel trick}), which
allows SVR to capture nonlinear relationships.
The most common choice is the radial basis function (RBF) kernel
\begin{equation}
    K(\mathbf{x}_i, \mathbf{x}) =
    \exp\left( -\gamma \lVert \mathbf{x}_i - \mathbf{x} \rVert_2^2 \right)
\end{equation}
where $\gamma$ controls how far the influence of each support vector
reaches. As with KNNR, the features are often required standardisation and
scaling, since both the margin and the kernel depend on distances
between points.

Kernel SVR shares the main weakness of KNNR as it must store
every support vector for kernel calculation. Thus kernel SVR is likely to
exceed the memory limit of constrained devices. Each prediction also
evaluates the kernel against
every support vector, which costs $O(|\mathcal{S}|\,m)$ operations,
each involving an exponential that requires floating-point
arithmetic. Linear SVR avoids these costs: it stores only $m+1$
coefficients and can be converted to fixed point in the same way as
linear regression. We therefore evaluate linear SVR for quantisation.

\subsubsection{Gaussian Process Regression (GPR)}
% TODO: probably too much math
Gaussian process regression is a probabilistic model that predicts a
continuous numerical value along with a confidence interval
\cite{wangIntuitiveTutorialGaussian2023}. It assumes that the outputs
at any set of inputs follow a multivariate Gaussian distribution
$\mathbf{f} \sim \mathcal{N}(\boldsymbol{\mu}, \mathbf{K})$, whose
covariance is given by a kernel function. The GPR gives two outputs:
the predicted mean and the confidence interval.

Since GPR uses kernel function, it has similar disadvantages as
kernel SVR in which the prediction depends on all training points,
exceeding the 5\,KB limit. Each prediction also evaluates the
kernel against every training point, at a cost of $O(nm)$ for the
mean and $O(n^2)$ for the variance, and each kernel evaluation needs
an exponential that requires floating-point arithmetic. Furthermore,
we do not use uncertainty estimate in the objective function, thus
making the confidence interval output of GPR redundant.
We therefore exclude GPR from further evaluation.

\subsubsection{Decision Tree Regression}
% TODO: insert citation for this (e.g. Breiman et al., CART)
A decision tree predicts by asking a series of yes/no questions about
the input. Each internal node tests one feature against a threshold
and sends the input to its left or right child depending on the
answer. The input follows this
path from the root until it reaches a leaf, and the value stored in
that leaf is the prediction, which in regression is the mean output
of the training points that reach that leaf.

The tree is built top-down. At each node, picks the feature to split that most
reduces the error of the prediction. For regression, this error is
the squared error, so the chosen split of the node's training points
$S$ into a left part $S_L$ and a right part $S_R$ maximises
\begin{equation}
    \Delta = \mathrm{MSE}(S)
    - \frac{|S_L|}{|S|}\,\mathrm{MSE}(S_L)
    - \frac{|S_R|}{|S|}\,\mathrm{MSE}(S_R),
    \qquad
    \mathrm{MSE}(S) = \frac{1}{|S|} \sum_{i \in S}
    \left( y_i - \bar{y}_S \right)^2,
\end{equation}
where $\bar{y}_S$ is the mean output of the points in $S$. This process
stops when the tree reaches a maximum depth or when a split would
leave fewer than a minimum number of points in a leaf. Both controls
the size of the tree and are chosen by a hyperparameter search.

% TODO: review this
The decision tree fits our requirements well. A trained tree converts
directly into nested \texttt{if}--\texttt{else} statements in C, and
each prediction makes at most $d$ comparisons, regardless of the
number of features or training points. Because every feature is an
integer, each threshold can be rounded down to an integer without
changing any decision, so inference needs no floating-point
arithmetic at all. The only rounding is in the leaf values, which are
rounded to the nearest integer in the $[0, 65535]$ PDR range. The
tree also needs no feature scaling, since each split only compares
one feature with a threshold. It handles small discrete counts, such
as hop count, naturally, and it can separate the sentinel values for
unknown features from real measurements with a single split. Unlike
a linear model, it can also capture threshold effects, such as PDR
dropping sharply once a parent nears congestion. The main weakness of
a single tree is that its output is piecewise constant and it can
overfit the training data, which the depth and leaf-size limits help
to control.

\subsubsection{Ensemble Tree}
% TODO: insert citation for random forest (Breiman 2001)
An ensemble combines many decision trees to reduce the overfitting of
a single tree. The two most common ensembles are random forests and
gradient-boosted trees. A \emph{random forest} trains each tree on a
random sample of the training data and features, and averages their
predictions. In our preliminary experiments, the random forest
performed similarly to a single decision tree while being many times
larger, so we did not consider it further.

% TODO: insert citation for LightGBM (Ke et al., 2017)
\emph{Gradient boosting} instead builds the trees one after another,
with each new tree correcting the errors of the trees before it. The
prediction after $K$ trees is
\begin{equation}
    F_K(\mathbf{x}) = F_0 + \eta \sum_{k=1}^{K} f_k(\mathbf{x}),
\end{equation}
where $F_0$ is the mean output of the training data, $f_k$ is the
$k$-th tree and $\eta$ is the learning rate, which shrinks each
tree's contribution to make the ensemble less likely to overfit.
With squared error, each tree $f_k$ is fitted to the residuals
$y_i - F_{k-1}(\mathbf{x}_i)$ left by the previous trees.

We use LightGBM's \texttt{LGBMRegressor}, a fast implementation of
gradient boosting. Unlike a standard decision tree, which grows
level by level, LightGBM grows each tree leaf by leaf, always
splitting the leaf that reduces the error the most. This gives more
accurate trees for the same number of leaves, which suits our tight
size budget. LightGBM also finds splits from histograms of the
feature values instead of trying every threshold, which speeds up
training. We set the learning rate to $\eta = 0.1$, and train each
tree on a random 80\% of the training points and 80\% of the
features to reduce overfitting. The number of trees (10 to 50), the
number of leaves per tree (7 to 31), the maximum depth (3 to 7) and
the minimum number of points per leaf (5 to 20) are chosen by a
hyperparameter search.

LightGBM keeps all of the decision tree's advantages on constrained
devices. Each tree converts to C in the same way as a single decision
tree, with integer thresholds. Since LightGBM stores each leaf value
with the learning rate and the starting value $F_0$ already applied,
the prediction is simply the sum of one leaf value from each tree,
which is computed with a 32-bit integer and clamped to the
$[0, 65535]$ range. Rounding each leaf value to an integer adds an
error of at most half a unit per tree, which is negligible on this
scale. The cost is size: the model grows with the number of trees and
leaves, so these must be kept small enough to fit within the
10\,KB limit.

In the end, we proceed with the decision tree and LightGBM, as both
are accurate enough to model PDR while being simple enough in design
and computation to run on our constrained devices.
