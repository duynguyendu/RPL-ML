\section{Regression Machine Learning Model Selection}
Running a machine learning model on constrained devices, with limited
computation
power, memory and energy, imposes strict requirements. The model must
be lightweight and fast at inference. Most microcontrollers used in
low-power networks have no floating-point unit, so floating-point
operations are emulated in software. That emulation is slow,
energy-hungry and adds to the code size. A common
solution is \emph{quantisation}, which represents the model's
parameters and inputs as fixed-point integers \cite{TODO-quantisation}.
However, quantisation can lower accuracy, and some models are much more
sensitive to it than others. The chosen model must therefore either
need no floating-point arithmetic at all, or keep its accuracy after
quantisation.

In this work, every input feature is kept in its native integer type,
as reported by the RPL stack (for example, ETX as a 16-bit
fixed-point value and hop count as an 8-bit integer). The predicted
PDR is scaled to an unsigned 16-bit integer in the range
$[0, 65535]$. Specifically, the model must:
% TODO: include reason for 10KB
\begin{itemize}
    \item Compile to C code of less than 10\,KB, and
    \item Use no floating-point operations during inference.
\end{itemize}

With these requirements in mind, we considered eight regression
models: K-nearest neighbour regression, linear regression, support
vector regression, Gaussian process regression, decision tree, random
forest, gradient-boosted trees (LightGBM) and the multilayer
perceptron. Each is described below, along with whether it meets
the requirement of size constrained. In model evaluation, we analyse weather the model fit in the floating-point requirement.

\subsubsection{K-Nearest Neighbor Regression (KNNR)}
KNNR is a common nonparametric supervised learning model
\cite{KNNRSONG201726}. A model is \emph{nonparametric} when it does
not assume a fixed functional form for the relationship between the
inputs and the output, and so has no fixed set of parameters to
learn. Instead, the training data itself forms the model, and its
complexity grows with the size of the data.

KNNR rests on the idea that points close to each other in feature
space have similar output values. To predict the value of an unseen
point $\mathbf{x}$, it finds the $k$ training points nearest to
$\mathbf{x}$, written $\mathcal{N}_k(\mathbf{x})$, and averages their
outputs:
% TODO: probs simplify the equation
\begin{equation}
    \hat{y}(\mathbf{x}) = \frac{1}{k}
    \sum_{i \in \mathcal{N}_k(\mathbf{x})} y_i
\end{equation}
Alternatively, each neighbour can be weighted by the inverse of its
distance to $\mathbf{x}$, so that closer neighbours contribute more
to the prediction:
\begin{equation}
    \hat{y}(\mathbf{x}) =
    \frac{\sum_{i \in \mathcal{N}_k(\mathbf{x})} w_i \, y_i}
    {\sum_{i \in \mathcal{N}_k(\mathbf{x})} w_i},
    \qquad w_i = \frac{1}{d(\mathbf{x}, \mathbf{x}_i)}
\end{equation}

The distance between two points with $m$ features is most commonly
measured by the Euclidean distance:
\begin{equation}
    d(\mathbf{x}, \mathbf{x}_i) =
    \sqrt{\sum_{j=1}^{m} \left( x_j - x_{i,j} \right)^2}
\end{equation}
% TODO: probs no need to include this many distances
Other common choices include the Manhattan distance, the Minkowski
distance (which generalises the Euclidean and Manhattan distances),
the Chebyshev distance and the Mahalanobis distance, which accounts
for correlations between features. The value of $k$ depends on the
application and is usually chosen by a hyperparameter search. Because
KNNR relies on distances between points, features with large ranges
can dominate those with small ranges, so normalising or scaling the
features often improves its accuracy.

KNNR needs no training: the model simply stores the training data
and uses it at inference. This also makes it easy to update, as new
observations can just be added to the stored data. However, this is
also one of its main weaknesses. KNNR does not scale well to large
datasets or high-dimensional feature spaces, and it is sensitive to
noise, outliers and missing values.

Although KNNR is simple, it does not meet our requirements. The whole
training dataset must be stored on the device, which far exceeds the
10\,KB limit. Each prediction must also compute the distance to every
one of the $n$ training points, at a cost of $O(nm)$, which is too
expensive for a constrained device.

\subsubsection{Gaussian Process Regression (GPR)}
GPR is a probabilistic supervised machine learning model. It makes
prediction by incorperating the knowledge from the kernel and
provides the uncertainty measure over its prediction
\cite{wangIntuitiveTutorialGaussian2023}.

Use multivariate Gaussian distribution
\begin{equation}
    P_X(x) = \frac{1}{\sqrt{2\pi}\,\sigma} \exp\left( -\frac{(x -
    \mu)^2}{2\sigma^2} \right).
\end{equation}

training dataset to a Gaussian Distribution and then join them
together to create a probabilistic prediction functions.
